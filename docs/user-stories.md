# 用户故事与验收场景

> 文档版本：1.0 ｜ 更新日期：2026-11-16 ｜ 依据 Issue #54 整理
>
> 本文从**产品/用户视角**描述用户故事、主流程、异常流程与验收标准。
> 技术架构、模块职责、依赖关系与数据流见 `docs/architecture.md`；
> 错题统计与推荐的精确口径见 `docs/mistake-business-rules.md`。

`user_id` 仅用于数据隔离，不是真实身份认证（详见 architecture.md 第 11.2 节）。

## 故事一：多源知识采集

**用户故事**：作为学习者，我希望把 PDF、Word、Markdown、代码文件或网页链接收进知识库，系统自动解析、切分并建立向量索引，以便后续检索和问答。

**主流程**
1. 用户上传文件或提交 URL，可选择是否公开。
2. 系统写入临时文件 → 提取文本 → 分块 → 逐块生成 Embedding。
3. 向量成功后，临时文件转为正式文件，Document 与 Chunk 在同一事务入库。
4. 返回文档 ID、标题与分块数。

**异常流程**
- 文本类文件解析为空：终止收录，不留半成品（HTTP 4xx）。
- URL 非 http/https 或缺少主机名：拒绝收录；保留用户原始 `source_url`。
- 任一分块 Embedding 失败：整次收录失败，无部分入库数据。
- 数据库提交或文件转正式失败：补偿清理临时/正式文件；清理失败记录路径、阶段与原因，不静默跳过。

**验收标准**
- 收录完成后可通过正文接口读到内容，检索可命中新分块。
- 失败场景下数据库与文件系统均无残留半成品。
- 图片/视频仅占位，明确不参与语义检索。

## 故事二：资料组织与管理

**用户故事**：作为知识库主人，我希望用文件夹和标签组织文档、修改元信息，并能删除、恢复或彻底删除文档，以便长期维护资料。

**主流程**
1. 创建/重命名/删除文件夹，把自有文档加入或移出文件夹。
2. 创建/置顶标签，为自有文档关联标签，按标签筛选。
3. 修改文档标题或公开状态。
4. 软删除文档 → 可在回收状态恢复；确认不再需要后彻底删除。

**异常流程**
- 对他人文档或无权限文件夹执行加入/修改/删除：返回错误，不改变数据。
- 已软删除文档不出现在列表、文件夹详情、检索结果和正文读取中。
- 彻底删除需文档已处于软删除状态；删除时登记孤立文件清理清单，文件清理失败不回滚数据库，可幂等重试。

**验收标准**
- 仅所有者能修改/删除自己的资源（#47/#48）。
- 删除—恢复—彻底删除的完整生命周期可验证，文件补偿清单可追踪。
- 标签全局唯一、置顶全局一致、有关联文档的标签禁止删除（#51）。

## 故事三：检索与智能问答

**用户故事**：作为学习者，我希望用自然语言提问，系统结合关键词与语义检索找到相关资料并生成带来源的回答。

**主流程**
1. 用户输入问题，系统做查询改写。
2. 通过检索适配器并行检索，合并、去重、排序；质量不足时补充检索一轮。
3. 由模型生成答案并给出资料溯源。

**异常流程**
- Embedding 服务不可用：降级为关键词检索，仍返回结果。
- 检索或生成出错：记录执行步骤状态，不直接崩溃。
- Agent 不直接接触数据库，检索范围由 API 层适配器传入。

**验收标准**
- 回答附带相关来源；已软删除文档不出现在检索结果（#47）。
- 检索访问范围过滤暂未实现（#46），不得借工程整理提前改变 search / Agent 行为。

## 故事四：多用户与知识共享

**用户故事**：作为用户，我希望能把文档或文件夹设为公开、在广场浏览他人公开资料、收藏感兴趣内容，同时自己的私有数据不被他人看到。

**主流程**
1. 切换模拟用户；用户 A 将资源设为公开。
2. 用户 B 在广场/作者主页看到 A 的公开资源，可收藏。
3. 用户 B 查看自己的收藏列表。

**异常流程**
- 用户 B 通过猜测 doc_id 读取 A 的私有正文：返回 404，不泄露存在性（#50）。
- 收藏私有文档/文件夹被拒绝；已软删除资源不出现在收藏列表（#49）。
- 公开文件夹不再批量修改其文档的公开状态（#48）。

**验收标准**
- 正文读取、收藏、列表遵循统一可见性口径：未删除 且（所有者本人 或 已公开）。
- 广场/作者主页/收藏列表只展示当前浏览者有权看到的内容。
- 跨用户改状态、复习、删除均被拒绝（#53 集成测试覆盖）。

## 故事五：错题管理与复习

**用户故事**：作为学习者，我希望记录错题与知识点，跟踪复习状态，看到薄弱知识点和个性化复习建议，从而有针对性地巩固。

**主流程**
1. 新增错题（题目、答案、错误原因、知识点），状态初始为 pending。
2. 修改状态与完成复习分离：完成复习会新增一条复习记录并更新累计次数/最近复习时间。
3. 查看知识点统计、学习概览与趋势（UTC 口径）。
4. 系统按规则对 pending/reviewing 错题评分排序，给出优先级与推荐理由。

**异常流程**
- 跨用户查看/修改/复习/删除他人错题：一律拒绝（#53 集成测试）。
- 复习写入中途失败回滚，不留部分更新。
- 已掌握（mastered）错题不进入推荐。

**验收标准**
- 错题总数为实际存在记录；累计次数与复习记录条数分别统计。
- 权重、阈值、排序与推荐理由与 `docs/mistake-business-rules.md` 一致。
- 删除错题时其复习记录通过 ORM 级联清理；不破坏 #53 已验收规则。

## 故事六：模拟用户上下文

**用户故事**：作为演示者，我希望切换用户后，各接口只处理当前用户的数据。

**主流程**
1. 前端在个人数据请求中传 `user_id`。
2. 后端 `get_current_user` 统一校验：缺失 422、格式错误 400、不存在 404。

**异常流程**
- 作者主页路径参数 `author_id` 表示被查看目标，与当前操作者是两个概念，不混用。
- 全局标签、置顶标签等共享状态不按用户过滤。

**验收标准**
- 所有需要身份的接口都接入当前用户上下文（公开浏览类接口按既有裁决不强制）。
- 明确声明这不是真实身份认证。
